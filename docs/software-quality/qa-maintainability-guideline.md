# 유지보수성 점검 항목

의도한 대로 고칠 수 있는 정도를 뜻한다.

**이 문서는 판정용이다.** 항목과 판정 기준만 담고, 왜 그 기준인지와 예시 코드는
[qa-maintainability-rationale.md](./qa-maintainability-rationale.md) 에 있다.

## 1. 모듈성

도메인 경계, 순환 의존, 내부 타입 교환의 판정 기준은 **backend 저장소가 소유한다.**
`domain-package-boundary-guideline.md` 가 패키지 구조와 ArchUnit 규칙까지 명시하고 있어 더 구체적이다.

## 2. 시험성

점검 항목
* `[코드]` `MNT-2-01` Controller에 비즈니스 로직이 없는가
* `[코드]` `MNT-2-02` 외부 의존성이 구현체가 아니라 추상화에 의존하는가
* `[코드]` `MNT-2-03` 시간, 랜덤, 현재 사용자 같은 암묵적 의존이 주입 가능한가
  현재 시각을 직접 호출하면 만료 로직을 테스트할 수 없다. `Clock` 을 주입한다.

테스트 실행 시간과 테스트 설계 자체의 품질은 backend 의 `unit-testing-guideline.md` 가 소유한다.

## 3. 수정성

점검 항목
* `[코드]` `MNT-3-01` 같은 로직이 여러 곳에 복사되어 있지 않은가
  중복 제거는 줄 수를 줄이는 일이 아니라 변경 지점을 하나로 모으는 일이다.
* `[코드]` `MNT-3-02` 매직 넘버가 상수로 분리되어 있는가
* `[설계]` `MNT-3-03` 정책 변경 시 고쳐야 할 파일 수를 예측할 수 있는가

판정 기준 (등급 C. 근거 없음. 검토를 유발하는 신호일 뿐이다)

| 항목 | 예시값 |
|------|--------|
| 중복 코드 비율 | 5% 이하 |
| 하나의 정책 변경이 건드리는 파일 수 | 3개 이하 |
| 메서드 길이 | 50줄 이하 |
| 클래스 길이 | 500줄 이하 |
| 메서드 파라미터 수 | 4개 이하 |

**길이 기준은 절대 규칙이 아니라 검토 신호다.** 넘었으면 한 번 들여다보라는 뜻이다.

## 4. 분석성

점검 항목
* `[코드]` `MNT-4-01` 이름이 역할을 드러내는가
* `[코드]` `MNT-4-02` 주석이 "무엇을"이 아니라 "왜"를 설명하는가
  코드가 이미 말하는 것을 반복하지 않고 코드만으로 알 수 없는 이유를 적는다.
* `[코드]` `MNT-4-03` 예외가 스택과 함께 남는가
  `e.getMessage()` 만 찍으면 스택을 버려 발생 위치를 알 수 없다. 예외 객체를 넘긴다.
* `[코드]` `MNT-4-04` 예외를 삼키지 않는가

운영 장애에서 가장 곤란한 상황은 무엇이 잘못됐는지 로그조차 없는 경우다.

## 5. 컨벤션 자동화

점검 항목
* `[인프라]` `MNT-5-01` 포맷터와 정적 분석이 빌드에 연결되어 있는가
  사람이 공백과 줄바꿈을 지적하는 것은 비용이 크고 감정 소모도 크다.
* `[인프라]` `MNT-5-02` 규칙 위반이 경고가 아니라 실패로 처리되는가
  경고를 허용하면 경고 수가 늘기만 하고 줄지 않는다. 0으로 두고 예외는 사유와 함께 억제한다.
* `[프로세스]` `MNT-5-03` 규칙 변경 시 기존 코드 일괄 적용 방침이 있는가

## 6. 측정 지표

| 지표 | 의미 | 기준 (예시값) |
|------|------|---------------|
| 순환 복잡도 | 분기 수 기반 복잡도 | 메서드당 10 이하 |
| 중복 코드 비율 | 복사된 로직의 양 | 5% 이하 |
| 도메인 간 순환 참조 | 구조 건전성 | 0건 |
| 변경 리드타임 | 커밋부터 배포까지 | 1일 미만 (등급 B) |
| 변경 실패율 | 배포 중 장애를 유발한 비율 | 약 5% (등급 B) |
| 테스트 커버리지 | 실행된 코드 비율 | 목표로 삼지 않는다 |

**커버리지는 코드가 실행됐는지만 알려 줄 뿐 제대로 검증됐는지는 말해 주지 않는다.**
쓰려면 전체 비율이 아니라 변경분 기준으로 본다.

DORA 2024 보고서의 elite 집단 관측값 (등급 B)

| 지표 | 관측값 |
|------|--------|
| 배포 빈도 | 온디맨드 |
| 변경 리드타임 | 1일 미만 |
| 변경 실패율 | 약 5% |
| 장애 복구 시간 | 1시간 미만 |

이 수치는 권장 목표가 아니라 상위 약 19% 집단의 관측 분포다.
DORA 자신이 변경 실패율은 다른 지표와 다르게 움직이는 이상치였다고 보고했으므로
절대 기준이 아니라 현재 위치를 가늠하는 참고선으로 쓴다.
